# 用語集

このリポジトリの文書で使っている用語を、競馬・統計・ソフトウェアの分野ごとに私なりにまとめました。

## 競馬・大会に関する用語

| 用語 | 意味 |
|---|---|
| 仮想ポイント | 大会内でのみ使われる得点。現金ではありません。初期値は1,000,000ptです。 |
| 券種 | 馬券の種類。このリポジトリでは主に三連単（1〜3着を着順どおりに当てる）と馬単（1・2着を着順どおりに当てる）を扱います。 |
| オッズ | 的中したときに賭け金の何倍が払い戻されるかを示す数字。 |
| 払戻率・控除率 | 売上のうち払戻に回る割合が払戻率、主催者が差し引く割合が控除率です。券種ごとにおおむね70〜80%が払戻に回ります。 |
| パリミュチュエル方式 | 売上から控除分を差し引いた残りを、的中者で分け合う方式。締切まで賭けが集まり続けるため、賭けた時点のオッズと確定オッズは一致しません。 |
| オーバーラウンド | オッズの逆数をすべて足すと1を超える、その超過分。控除率に相当します。 |
| 印 | 大会で各馬に付ける予想の記号（◎○▲△など）。私は市場の人気順から機械的に付けていました。 |

## 統計・モデルに関する用語

| 用語 | 意味 |
|---|---|
| 市場確率 | オッズの逆数から控除分を取り除き、合計が1になるよう正規化した確率。 |
| Harville モデル | 各馬の勝率から着順の確率を求める古典的な方法。1着馬を除いた残りの馬が、勝率の比を保ったまま2着を争うと仮定します。人気薄の馬の入着確率を低めに見積もる傾向が知られています。 |
| 対数線形モデル | 確率の対数を特徴量の重み付き和で表すモデル。このリポジトリでは重みが2つだけの小さなものを使っています。 |
| NLL（負の対数尤度） | 実際に起きた結果にモデルがどれだけ低い確率を付けたかの指標。小さいほど予測が良いことを示します。 |
| holdout | 学習に使わず、評価のためだけに取っておくデータ。このリポジトリでは日付で区切り、後半の日付を holdout にしています。 |
| 優位性（エッジ） | 市場の予想を上回る予測力。これがあれば長期的に払戻率が100%を超えますが、このリポジトリの手法にはありません。 |
| 動的計画法 | 最後のレースから逆向きに「その時点でどう動くのが最善か」を計算していく方法。 |
| 方策表 | 動的計画法の計算結果を「状態（残りレース数・所持ポイント）→ 行動（券種・価格帯・点数・金額）」の表にしたもの。 |
| 到達確率 | 最終的に目標の所持ポイントに届く確率。 |

## ソフトウェアに関する用語

| 用語 | 意味 |
|---|---|
| 計画ファイル（計画バンドル） | 1日分の各レースで何をいくら買うかを確定させたJSONファイル。内容のハッシュ値を含みます。 |
| ハッシュ値（SHA-256） | ファイルの内容から計算される固定長の値。1文字でも内容が変われば値が変わるため、改ざんや取り違えの検出に使います。 |
| ドライバ | 投票の送信先を切り替える部品。`paper`（模擬投票）と `live`（本番）の2つがあります。 |
| 模擬投票（paper） | 実際には送信せず、手元のファイルに投票を記録する動作。大会期間外でもすべての処理を試せます。 |
| 送信許可（arm） | 運用者が計画のハッシュ値を入力し、その日の送信を明示的に許可する操作。コマンドは `votectl arm-day` です。 |
| 照合 | 送信後に大会側の記録を読み返し、送った内容と一致するかを確かめる処理。 |
| ジャーナル | 処理の経過を追記のみで残す記録ファイル。プロセスが止まっても、ここから状態を復元します。 |
| fail-closed | 状況が判断できないときに、処理を続けるのではなく止める側に倒す設計方針。 |
| 緊急停止ファイル | このファイルが存在する間は一切送信しない、という仕組み。ファイルを置くだけで止められます。 |
| launchd | macOS に標準で備わっている、プログラムの常駐や定期実行を管理する仕組み。 |

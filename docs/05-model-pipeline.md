# モデル構築パイプライン

```
判断時点のオッズ
   │
   ├─► 市場確率        （控除分を除く。推定するパラメータはなし）
   └─► Harville 順序確率（単勝オッズから）
   │
   ▼
2つの重みの対数線形モデル  ──►  確率 = 0.95 × 市場確率 + 0.05 × モデル
   │
   ├─ 方策表を使う場合: (残りレース数, 所持ポイント) → 価格帯・点数・1点あたりの金額
   │                     その価格帯に最も近い組合せを選ぶ
   └─ 目標残高を使う場合: 候補の絞り込み → 必要な金額 → ナップサック問題で配分
   │
   ▼
計画ファイル（ハッシュ値つき） ──►  votingd
```

この文書で説明するのは `pykeiba/`、つまり私が大会で使った手法を汎用化して書き直したものです。大会中に実際に動かしたスクリプトは [submission/](../submission/) にあります。

## 特徴量

各レースで、オッズが出ている三連単のすべての組合せについて、次の2つの値を使います。どちらも市場から得られる値です。

1. 三連単のオッズそのものから求めた、控除分を除いた確率の対数
2. 単勝オッズから Harville モデルで求めた確率の対数

控除分は、オッズの逆数をその合計で割るという単純な方法で取り除きました。推定するパラメータが要らない方法はこれしかないためです。より複雑な方法を使うと、本来は「市場の見方」であるはずの列に、こちらで推定した値が混ざってしまいます。

Harville モデルは、1着馬を除いた残りの馬が、勝率の比を保ったまま2着以下を争うと仮定します。この仮定は、人気薄の馬が上位に入る確率を低めに見積もるという方向に偏ることが知られています。そのため私は、Harville の確率を単独の予測としては使わず、市場から得られる2つ目の値として扱いました。

## 学習

各レースについて、オッズが出ている組合せ全体の上で確率分布（softmax）を作り、実際に的中した組合せが選ばれる確率を最大化します。1レースは1つの観測として数えます。馬券1枚ごとに数えるわけではないため、数百レースあっても標本としては小さいことに注意してください。

最小化するのは、レースごとの負の対数尤度（NLL）の平均に、正則化の項を加えたものです。正則化の項は、市場確率の重みを1に、Harville の重みを0に近づけるように働きます。つまり「オッズだけを使い、それ以外は使わない」状態を基準にしており、そこから離れるには、それに見合うだけ予測が良くなる必要があります。重みの範囲は `[0.5, 1.5]` と `[0, 0.5]` で、最適化には L-BFGS-B を使っています。

学習と評価は日付で分けています。`--holdout-from YYYYMMDD` を指定すると、その日付以降のレースは評価用（holdout）として取っておかれ、学習には一切使われません。

### 結果の読み方

同梱の合成データでは、重みは `[0.935, 0.0]` 付近になり、holdout の NLL は 5.80 のうち約 0.015 改善します。

Harville の重みは、範囲の下限である0になります。これは不具合ではなく、三連単のオッズがすでに与えられている場合、単勝オッズから求めた Harville の確率は新しい情報を加えなかった、という結果です。情報のほとんどは市場の確率が持っています。

0.015 程度の改善は、馬券で利益が出ることの根拠にはなりませんし、確率が正確であることの根拠にもなりません。私自身、この数字をそのように受け取らないよう気をつけていました。

## 方策表

大会のように、レース数が決まっていて、所持ポイントを一定の水準まで増やすことが目的の場合、最善の行動はその時点の状況によって変わります。そこで私は、次の組合せについて、最後のレースから逆向きに最善の行動を計算することにしました（動的計画法）。

```
状態 = (残りレース数, 所持ポイント)
行動 = (価格帯, 点数, 1点あたりの金額)
```

価格帯ごとに払戻率 `R` を設定し、オッズ `O` の馬券1枚が的中する確率を `R ÷ O` とします。`R` が1未満であれば、どの行動も平均すると損をします。方策表が決めているのは、利益の出る賭け方ではなく、**いつリスクを取るか**です。

同梱の価格帯の払戻率は、公表されている控除率をもとにした目安の値で、実際に測定した値ではありません。計算結果を参考にされる場合は、ご自身で測定した値に置き換えてください。なお、`R` に1より大きい値を与えると、ソルバはそれを市場を上回る優位性として扱い、そのまま計算してしまいます。

### 計算結果が過大にならないようにした2つの工夫

**所持ポイントは切り捨てで扱うことにしました。** 計算の都合上、所持ポイントは一定の刻みで区切って扱います。賭けた後の所持ポイントは、その値以下で最も近い刻みの値として評価します。こうすると状態の価値を低めに見積もることはあっても、高く見積もることはありません。四捨五入で扱うと、約半数の遷移で価値が高く見積もられ、最適化はちょうどその部分を選んでしまいます。このため、表示される到達確率は、実際の到達確率の下限となります。

**理論上の上限と照合しています。** ポイントは払戻率の分しか戻ってこないため、到達確率には

```
P(到達) ≤ 最大払戻率 × 初期資金 ÷ 目標
```

という上限があります。計算結果がこれを超えた場合、ソルバは表を出力せずに停止します。この検査は、開発中に実際の誤りを見つけてくれました。四捨五入で扱っていた最初の実装は、上限 0.4211 に対して 0.4823 という値を出しており、区切り方の誤差からポイントを生み出していたのです。

刻みの細かさは、精度と計算時間のかね合いで決まります。`--bank-grid 25000` では 0.296、5,000 では 0.397、2,500 では 0.408 となり、いずれも上限の 0.421 を下回り、1秒未満で計算できます。

### シミュレーションで確かめる

```bash
.venv/bin/python -m pykeiba verify --table out/policy_table.json
```

できた方策表に従って、同じ払戻率の仮定のもとでレースを繰り返しシミュレーションします。計算上の値 0.397、シミュレーションでの到達率 0.406、上限 0.421 と、互いに矛盾しない結果になっています。計算上の値がシミュレーションの結果を上回った場合は、計算に誤りがあります。

あわせて、最終残高の平均（1,000,000 に対して約 810,000）と中央値（約 35,000）も表示します。中央値がほぼゼロであることは、この方策が一か八かの賭けに近いことを示しています。

## 配分

特徴量を共通にして、2つの配分方法を用意しています。

**方策表を使う方法**: 現在の状態に対応する行を表から引き、指定された価格帯に最も近い `k` 個の組合せを、表の示す金額で買います。価格帯の中での順位は、価格の近さ（95%）とモデルの確率の順位（5%）を組み合わせて決めます。値そのものではなく順位を組み合わせるので、尺度の違う2つの値が互いに打ち消し合うことはありません。

**目標残高を使う方法**: どの馬券も、それ1枚が的中するだけで目標の所持ポイントに届くように金額を決めます。

```
金額 = 100 × 切り上げ((目標 − 所持ポイント + そのレースの予算) ÷ (100 × オッズ × odds_factor))
```

そのうえで、確率を金額で割った値の上位200候補について、100ポイント単位のナップサック問題を解きます。同じレースの馬券は同時には当たらないので、的中確率は選んだ馬券の確率の合計になります。

`odds_factor` の既定値は 0.80 です。締切まで賭けが集まり続けるため、的中した馬券は賭けた時点のオッズより低い倍率で払い戻されるのが一般的です。賭けた時点のオッズのまま金額を決めると、目標にわずかに届かないことが続きます。

どちらの方法も、1レースの予算の中では最適な配分を求めますが、複数のレースや他の参加者の動きまで考えた最適化ではありません。
